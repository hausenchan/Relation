# YYZ 生产配置变更与审批策略

本策略回答“商业化运营可以操作什么、谁来审批”。它约束 Agent 和人工执行，不替代 Relation 的
账号权限、操作日志和服务端鉴权。

## 分级

| 级别 | 典型动作 | Agent 权限 | 人工要求 | 默认审批 |
| --- | --- | --- | --- | --- |
| L0 只读 | 查配置、日志、报表和历史版本 | 可执行 | 无生产写入 | 不需要业务审批 |
| L1 草案 | 生成配置差异、测算、实验和回滚草案 | 可执行 | 不写生产 | 商业化运营负责人确认内容 |
| L2 业务配置 | 媒体单价、预算比例、容量、任务排序、广告位、奖励、上下线 | 不可直接执行 | 授权运营人员执行 | YYZ 项目负责人审批 |
| L3 高风险/跨组织 | 新合同、结算规则、法务、财务、域名、账号、生产代码发布 | 不可直接执行 | 路由对应组织能力 | 对应组织审批人 + YYZ 项目负责人 |

## 默认 MVP 边界

- Agent 只能读取配置、生成变更草案和模拟影响。
- 任何生产写入均由授权人工执行，并保留变更前后值、审批人、执行人和时间。
- 单价、奖励、流量比例、广告负载和预算上下线统一按 L2 管理。
- 法务、财务、合同、软著、域名、平台账号和公司级研发统一按 L3 管理。
- 暂无正式审批系统时，审批结果至少记录在 Relation 可审计任务中，不用口头消息替代。

## 紧急回滚

出现负毛利、错误发奖、严重回调异常、违规风险或大面积业务中断时，已授权运营人员可按预先批准的
回滚手册先恢复最近安全版本，并立即通知 YYZ 项目负责人。紧急回滚不能扩大配置范围或引入新策略。

## 后续演进

组织中台具备配置审批和执行 API 后，再把满足预设阈值的 L1/L2 操作升级为“机器草案、人工一键
审批、服务端执行”。在此之前不授予 Agent 生产写权限。
